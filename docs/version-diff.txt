版本正文对比（diff）使用说明
==============================

本文说明如何查看同一文档两次修订之间的正文变化。内容可与当前源码
直接核对，仅覆盖 diff 子命令，不展开其他功能。

对应源码
--------

- 命令行入口与参数定义：knowledge_base/__main__.py
  - build_parser()：注册 diff 子命令及其位置参数 id、必选参数
    --from 与 --to；id 与两个版本号均使用 positive_int 类型，
    只接受正整数。
  - main()：解析参数后调用 Store.diff(...)，返回文本非空时以
    UTF-8 原样写入标准输出；捕获 KBError 时把原因写入标准错误
    并以退出码 2 结束，成功时退出码为 0。
- 存储与差异生成：knowledge_base/store.py
  - Store.diff(doc_id, from_version, to_version)：先检查根路径，
    再经 Store.get_body 分别读取两侧版本正文，最后交给
    unified_body_diff 生成统一差异文本；文件头标签形如
    "<id>/v<N>.md"。
  - Store.get_body(doc_id, version)：按索引定位所选版本的正文
    文件，校验其存在、是普通文件且可按 UTF-8 解码。
  - unified_body_diff(old, new, from_label, to_label)：把 CRLF
    规范化为 LF 后按行比较，调用 difflib.unified_diff（n=3）
    生成统一差异；正文相同时返回空串。
  - _split_lines_keepends(text)：仅以 LF 划分行并保留行尾换行。

调用路径概括：命令参数（__main__.py 的 build_parser/positive_int）
→ main() 中的 diff 分支 → Store.diff → 两次 Store.get_body 读取
版本正文 → unified_body_diff 生成文本 → 标准输出。

示例前提
--------

以下示例基于一个已准备好的本地知识库（目录记为 KB_DIR）：其中
文档 ID 为 1，版本 1 的正文为两行“准备”“执行”，版本 2 的正文
为两行“准备”“验证”，每行末尾均为 LF。即：

    版本 1 正文：准备\n执行\n
    版本 2 正文：准备\n验证\n

正向对比：版本 1 → 版本 2
--------------------------

命令：

    python -m knowledge_base --root KB_DIR diff 1 --from 1 --to 2

预期标准输出（完整内容，UTF-8，行尾均为 LF）：

    --- 1/v1.md
    +++ 1/v2.md
    @@ -1,2 +1,2 @@
     准备
    -执行
    +验证

预期退出码为 0，标准错误为空。

逆向对比：版本 2 → 版本 1
--------------------------

命令：

    python -m knowledge_base --root KB_DIR diff 1 --from 2 --to 1

预期标准输出（完整内容，UTF-8，行尾均为 LF）：

    --- 1/v2.md
    +++ 1/v1.md
    @@ -1,2 +1,2 @@
     准备
    -验证
    +执行

预期退出码为 0，标准错误为空。逆向对比只交换两侧：--from 一侧为
旧侧（--- 文件头与 - 行），--to 一侧为新侧（+++ 文件头与 + 行），
增删方向随之对调。

输出格式约定
------------

- 文件头为 "--- <id>/v<from>.md" 与 "+++ <id>/v<to>.md"，使用
  文档 ID 与版本号构成的相对标签，不附加标题、绝对路径或时间戳。
- 区块头形如 "@@ -1,2 +1,2 @@"，给出旧侧与新侧的行号区间。
- 每处变化最多保留前后三行上下文；相邻变化（间隔不超过上下文
  窗口）会合并为同一区块。
- 以上示例只是正文对比的读取操作，不代表执行更新或回滚，知识库
  内容不变。

比较语义
--------

- 空正文可参与比较；两侧均为空或正文相同时无差异。
- 两侧正文有效且对比同一版本（--from 与 --to 相同），或两次修订
  仅标题不同而正文相同时，命令成功（退出码 0、标准错误为空）且
  标准输出为空，不输出文件头。
- 比较前把 CRLF 规范化为 LF，因此 CRLF 与 LF 的差别不产生差异，
  输出统一使用 LF。
- 末尾是否有换行仍会产生差异；缺少末尾换行的行之后带有
  "\ No newline at end of file" 标记行。
- 中文、空行、行内空白和 Markdown 符号一律按正文原文逐行比较，
  不渲染 Markdown，也不做格式化。

失败约定
--------

以下情形统一为：退出码 2，标准输出为空，原因写入标准错误（以
“错误: ”开头，不泄露堆栈）：

- 必要参数缺失（id、--from 或 --to 未给出）；
- 文档 ID 或版本号不是正整数（如 0、负数、小数、非数字文本）；
- 文档不存在，或任一所选版本不存在；
- 根目录不存在或目录下尚无索引（不会因此创建目录或索引）；
- 根路径不是目录；
- 已有索引无法打开或查询；
- 任一所选正文缺失、不是普通文件，或不能按 UTF-8 解码。

即使 --from 与 --to 是同一版本，两侧也各自完整执行正文有效性
检查；检查失败即报错，不会回退到其他版本，也不会产出半份差异。

只读保证
--------

无论成功或失败，diff 都不新建知识库、不修改已有正文与索引、不
增加历史版本；其他现有命令（add、update、show、history、search）
保持原行为。
