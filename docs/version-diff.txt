版本正文对比（diff）使用说明
==============================

本文说明如何用 diff 子命令查看同一文档两次修订之间的正文变化。
文中结论均可与当前源码核对，主要依据：

- knowledge_base/__main__.py
  - build_parser()：注册 diff 子命令及 id、--from、--to 参数，
    三者均经 positive_int 校验为正整数，--from 与 --to 为必填。
  - main()：把参数交给 Store.diff()，将返回的差异文本原样写入
    标准输出；捕获 KBError 时把原因写入标准错误并以退出码 2 结束。
- knowledge_base/store.py
  - Store.diff()：校验根路径是目录，经 Store.get_body() 分别读取
    两个版本的正文，再交给 unified_body_diff() 生成统一差异。
  - Store.get_body()：经 _require_initialized() 与
    _require_document() 校验索引与文档存在，按版本号查出正文路径，
    校验正文文件存在、是普通文件且能按 UTF-8 解码。
  - unified_body_diff()：把 CRLF 规范化为 LF 后按 LF 分行
    （_split_lines_keepends()），调用 difflib.unified_diff（n=3）
    生成差异；文件头只用 "ID/vN.md" 形式的相对标签。

调用路径：命令行参数（argparse，positive_int 校验）→ main() →
Store.diff() → Store.get_body()（读索引与正文文件）→
unified_body_diff()（生成统一差异文本）→ main() 写入标准输出。
diff 只读取知识库，不执行更新或回滚。

示例前提
--------

已有一个初始化好的本地知识库目录（下文以 KB_DIR 代指），其中：

- 文档 ID 为 1；
- 版本 1 的正文为两行「准备」「执行」，每行末尾均为 LF；
- 版本 2 的正文为两行「准备」「验证」，每行末尾均为 LF。

即版本 1 正文为 "准备\n执行\n"，版本 2 正文为 "准备\n验证\n"。

正向对比（版本 1 → 版本 2）
---------------------------

命令：

    python -m knowledge_base --root KB_DIR diff 1 --from 1 --to 2

预期标准输出（完整内容，每行以 LF 结束）：

    --- 1/v1.md
    +++ 1/v2.md
    @@ -1,2 +1,2 @@
     准备
    -执行
    +验证

退出码为 0，标准错误为空。

输出解读：前两行是文件头，--- 一侧为 --from 指定的旧版本（1/v1.md），
+++ 一侧为 --to 指定的新版本（1/v2.md）；@@ -1,2 +1,2 @@ 表示旧侧
从第 1 行起共 2 行、新侧从第 1 行起共 2 行参与本区块；以空格开头的
「准备」是两侧相同的上下文行，-执行 表示旧侧有而新侧删除的行，
+验证 表示新侧增加的行。

逆向对比（版本 2 → 版本 1）
---------------------------

命令：

    python -m knowledge_base --root KB_DIR diff 1 --from 2 --to 1

预期标准输出（完整内容，每行以 LF 结束）：

    --- 1/v2.md
    +++ 1/v1.md
    @@ -1,2 +1,2 @@
     准备
    -验证
    +执行

退出码为 0，标准错误为空。交换 --from 与 --to 后，文件头两侧随之
交换，增删方向也相应反转：原来的新增行变为删除行，反之亦然。

输出格式约定
------------

- 文件头固定为 --- ID/vN.md 与 +++ ID/vM.md，使用知识库内的相对
  标签，不附加文档标题、绝对路径或时间戳。
- 差异按区块（hunk）呈现，区块头 @@ -a,b +c,d @@ 给出两侧的起始
  行号与行数区间；每处变化最多保留前后各三行上下文。
- 相邻变化之间的间隔不超过上下文窗口时合并为同一区块，间隔更大时
  分成多个区块。
- 输出统一使用 LF，不包含 CR。
- 上述示例只是正文对比，不执行更新或回滚，知识库内容不变。

比较规则
--------

- 空正文可以参与比较：空正文与非空正文对比时，空的一侧在区块头中
  以起始行 0、行数 0 表示（如 @@ -0,0 +1,2 @@）。
- 两侧正文有效且完全相同（包括对比同一版本，或两次修订仅标题不同）
  时，命令成功（退出码 0、标准错误为空），标准输出为空，不输出
  文件头。
- 比较前把 CRLF 规范化为 LF，因此仅换行风格不同（CRLF 与 LF）不
  产生差异。
- 末行是否带换行仍算差异：缺少末尾换行的一侧，该行之后输出一行
  「\ No newline at end of file」标记。
- 中文、空行、行内空白和 Markdown 符号一律按正文原文逐行比较，
  不渲染 Markdown，也不做任何格式化。

失败约定
--------

以下任一情形，命令以退出码 2 结束，标准输出为空，原因写入标准错误：

- 缺少必要参数（id、--from 或 --to 缺失）；
- 文档 ID 或版本号不是正整数（如 0、负数、小数、非数字）；
- 文档不存在，或任一所选版本不存在；
- 根目录不存在或目录下尚无索引；
- 根路径不是目录；
- 已有索引无法打开或查询；
- 任一所选正文文件缺失、不是普通文件或不能按 UTF-8 解码。

对比同一版本时仍会校验该版本正文是否有效；校验失败即报错，不会
回退到其他版本。

只读保证
--------

无论对比成功或失败，diff 都不会新建知识库目录或索引，不修改已有
正文与索引，也不增加历史版本；add、update、show、history、search
等其他命令的行为不受影响。
